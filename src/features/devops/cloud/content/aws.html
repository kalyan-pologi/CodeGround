AWS for Spring Boot

Follow a realistic microservice deployment from identity and compute to storage, containers, event processing, and monitoring. Select a service to open its full lesson.

Learning path

IAM → EC2 → S3 → RDS → Secrets Manager → ECR → ECS → Lambda → CloudWatch. Each lesson covers purpose, internals, Reidy.AI usage, implementation, architecture, failure cases, interview questions, comparisons, and revision notes.

01 · Identity

IAM

Controls which people and workloads may call AWS APIs. Start here to understand roles and least privilege.

Open IAM → 02 · Compute

EC2

Virtual machines for running Spring Boot when you need direct control over the host and runtime.

Open EC2 → 03 · Storage

S3

Private object storage for appraisal PDFs and other files, with keys stored in your database.

Open S3 → 04 · Data

RDS

Managed relational databases for appraisal records, transactions, backups, and failover.

Open RDS → 05 · Security

Secrets Manager

Encrypted storage and rotation for database credentials and external API tokens.

Open Secrets Manager → 06 · Delivery

ECR

A private registry for versioned Spring Boot container images that ECS can pull.

Open ECR → 07 · Containers

ECS

Runs and scales containerized services with task definitions, health checks, and deployments.

Open ECS → 08 · Events

Lambda

Runs bounded background work when events arrive, such as processing an uploaded report.

Open Lambda → 09 · Operations

CloudWatch

Collects logs and metrics, then turns them into dashboards and actionable alarms.
