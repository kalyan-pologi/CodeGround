Question: How do functional interfaces, lambda expressions, method references, and Optional work in Java 8?

Short answer

A functional interface has exactly one abstract method, such as Predicate, Function, Consumer, or Supplier. A lambda supplies the implementation, and a method reference is shorter syntax for a compatible existing method. Optional models a possibly absent return value; it is not a replacement for every nullable field or parameter.

import java.util.Optional;
import java.util.function.Function;

public class FunctionalDemo {
    @FunctionalInterface
    interface Discount { int apply(int price); }

    public static void main(String[] args) {
        Discount tenPercent = price -> price * 90 / 100;
        Function<String, String> normalize = String::trim;

        String name = Optional.ofNullable("  Ada  ")
                .map(normalize)
                .filter(value -> !value.isEmpty())
                .orElse("unknown");

        System.out.println(tenPercent.apply(100));
        System.out.println(name);
    }
}

Expected output: 90 and Ada.

Internal working and pitfalls

The compiler converts a lambda to a functional-interface instance, commonly through invokedynamic; it is not literally a new named method in source. Lambdas can capture only final or effectively final local variables. Method references still obey the target functional interface signature. Optional.map transforms a present value, flatMap avoids nested optionals, and orElseGet evaluates its fallback lazily while orElse evaluates it immediately.

  • Use Optional mainly for return values where absence is expected.
  • Do not call get() without checking; prefer orElseThrow or a transformation chain.
  • Do not put Optional in JPA entities or serialize it casually without understanding the framework contract.
  • Keep lambdas small and side-effect free, especially inside streams.

Follow-up questions

  • Can an interface have default methods? Yes. It may have many default or static methods, but only one abstract method to remain functional.
  • What is the difference between Predicate and Function? A predicate returns boolean; a function maps a value to another value.
  • Why is orElseGet often preferred? Its supplier runs only when the optional is empty, avoiding unnecessary work.

Interview-ready answer

A functional interface has one abstract method. Lambdas and method references provide implementations that the compiler targets to that interface, while Optional represents an absent-or-present return value. I use these features for clear transformations, avoid side effects and Optional.get, and choose orElseGet when fallback creation is expensive.

Functional interfaces in detail

InterfaceMethodExample use
Predicate<T>boolean test(T)Filtering or validation
Function<T,R>R apply(T)Mapping one type to another
Consumer<T>void accept(T)Side effects such as logging
Supplier<T>T get()Lazy creation or fallback computation
UnaryOperator<T>T apply(T)Transforming a value into the same type

@FunctionalInterface asks the compiler to enforce the one-abstract-method rule. Default and static methods do not count as abstract methods. A lambda is compatible with a target type, so the same lambda syntax can mean different things depending on the expected interface.

Lambda capture and method references

import java.util.function.*;

public class LambdaDetailsDemo {
    static String clean(String value) { return value.trim().toUpperCase(); }

    public static void main(String[] args) {
        String prefix = "ID-"; // effectively final
        Function<String, String> lambda = value -> prefix + clean(value);
        Function<String, String> reference = LambdaDetailsDemo::clean;

        System.out.println(lambda.apply("  a1  "));
        System.out.println(reference.apply("  hello  "));
    }
}

Expected output: ID-A1 and HELLO. A local variable captured by a lambda must be final or effectively final; otherwise its changing stack lifetime would not match the lambda's lifetime.

The compiler typically implements lambdas with invokedynamic. This is an implementation mechanism, not a reason to rely on a particular generated class name. Captured values are stored in the lambda object, so capturing large objects can unintentionally extend their lifetime.

Optional operations and common mistakes

import java.util.Optional;

public class OptionalDemo {
    static String city(String input) {
        return Optional.ofNullable(input)
                .map(String::trim)
                .filter(value -> !value.isEmpty())
                .orElseGet(() -> "unknown");
    }

    public static void main(String[] args) {
        System.out.println(city("  Chicago  "));
        System.out.println(city("   "));
    }
}

Expected output: Chicago and unknown. map converts a present value and turns a null mapper result into empty; flatMap is used when the mapper already returns an Optional. orElse evaluates its argument immediately, while orElseGet invokes the supplier only when needed.

  • Do not use Optional.get() as a disguised null check.
  • Do not use Optional for every field, setter, or method parameter unless the API convention explicitly requires it.
  • Be careful with orElse when the fallback performs I/O, allocates, or has side effects.
  • Use primitive variants such as OptionalInt when appropriate to avoid boxing.
  • A lambda can throw unchecked exceptions, but checked exceptions need handling or an adapter.

Real-world use

Use predicates for validation rules, functions for DTO mapping, consumers for metrics or audit events, suppliers for lazy defaults, and Optional for repository methods such as findById. Keep business side effects outside long transformation chains so failures and debugging remain clear.

Additional follow-up answers

  • Why are lambdas useful in streams? They represent behavior as values, allowing operations such as filtering and mapping to be composed.
  • Can a lambda modify a captured local variable? It cannot reassign a captured local variable, but it can mutate a referenced mutable object—which should be avoided in parallel pipelines.
  • What is the difference between a method reference and a lambda? A method reference is shorthand when an existing method already matches the target signature; both create behavior for a functional interface.
  • How is Optional different from null? Optional makes absence explicit in an API return type, but it does not eliminate all nulls or replace validation.
