Question: How does Spring Boot detect and start embedded Tomcat, and what is the precedence order for server.port?

Short answer

When servlet web classes and an embedded Tomcat implementation are on the classpath, conditional web-server auto-configuration creates a server factory and starts it during application-context refresh. The effective port comes from the highest-priority property source, commonly command-line arguments or deployment environment overrides, followed by configured application and profile files.

How to troubleshoot

  1. Check the effective server.port, bind address, and container port mapping.
  2. Check whether another process already owns the port.
  3. Check readiness and ingress configuration separately from the local listener.
  4. Use a random test port to avoid test collisions.
Embedded Tomcat is selected by classpath and conditional configuration; the port is a configuration result, so I verify the winning property source and the network path independently.

Startup details

During context refresh, Boot creates the web-server factory and applies customizers before calling the server lifecycle. A port of 0 asks the operating system for a free port, which is useful in tests. Binding to 127.0.0.1 inside a container can make the process unreachable even when the port is correct; production services normally bind to the container interface.

In a container, map the service port separately from the process port and verify that readiness probes use the same effective route.

Interview-ready answer

Boot selects embedded Tomcat from servlet and container classes on the classpath, creates its server factory during context refresh, and starts it. I diagnose port problems by checking property precedence, bind address, container mapping, and readiness independently.
