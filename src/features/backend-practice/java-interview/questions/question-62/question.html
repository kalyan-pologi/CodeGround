Question: How does Spring Boot load external configuration, resolve property precedence, and bind values with @Value and @ConfigurationProperties?

Short answer

Boot builds an Environment from ordered property sources such as command-line arguments, environment variables, profile-specific files, application files, and test overrides. Higher-priority sources win. Use @ConfigurationProperties for grouped, validated configuration and @Value for a small isolated value.

Diagnostic approach

  1. List the active profiles and effective property source.
  2. Check spelling, relaxed binding, and environment-variable naming.
  3. Use Actuator's environment/configuration views only with secured access.
  4. Prefer immutable configuration objects and fail fast on required values.

Common mistakes

  • Hard-coding secrets in files.
  • Using @Value for a large nested configuration tree.
  • Assuming the file in the packaged JAR overrides deployment environment variables.
I would identify the winning property source first, then verify binding and validation. Configuration should be external, typed, observable enough to diagnose, and protected from secret leakage.

Precedence and binding details

Command-line arguments and deployment environment overrides commonly outrank packaged files. Profile-specific documents override their base document when that profile is active. Relaxed binding maps names such as PAYMENTS_TIMEOUT to a kebab-case property. Constructor-bound configuration makes required settings explicit and testable.

Production example

If a timeout is 30 seconds in production even though the file says 2 seconds, compare the effective Environment with container variables, Helm values, command-line arguments, and remote configuration. Never print the value of a password or token while debugging.

Minimal binding example

@ConfigurationProperties("payments")
public record PaymentProperties(Duration timeout, URI endpoint) { }

Register it with configuration-properties scanning and validate required fields at startup. Test the effective environment for each deployment profile.

Interview-ready answer

Boot merges ordered property sources into an Environment, with deployment overrides winning over packaged defaults. I use typed, validated @ConfigurationProperties for groups of settings, then inspect the effective source when production differs from local.
