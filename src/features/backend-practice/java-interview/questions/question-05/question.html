Question: How do Java generics, type erasure, reflection, and annotations work internally?

Short answer

Generics provide compile-time type safety and are mostly implemented through type erasure, so ordinary generic type arguments are removed from runtime bytecode. The compiler inserts casts where needed. Reflection inspects classes, methods, fields, and annotations at runtime. Annotations are metadata whose retention determines whether they exist only in source, in class files, or at runtime.

Generics and type erasure

import java.util.*;

public class GenericsDemo {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("Maya");
        String name = names.get(0); // compiler inserts a cast to String
        System.out.println(name);

        System.out.println(names instanceof List<?>);
    }
}

Expected output:

Maya
true

At runtime, the JVM generally sees an ArrayList, not an ArrayList<String>. This is why List<String>.class is illegal and why instanceof List<String> is not allowed.

Reflection and annotations

import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Endpoint { String value(); }

@Endpoint("/orders")
class OrderController { }

public class ReflectionDemo {
    public static void main(String[] args) {
        Class<OrderController> type = OrderController.class;
        Endpoint endpoint = type.getAnnotation(Endpoint.class);
        System.out.println(type.getSimpleName());
        System.out.println(endpoint.value());
    }
}

Expected output:

OrderController
/orders

Frameworks such as Spring use reflection and runtime annotations to discover controllers, services, configuration, validation rules, and dependency injection metadata.

Important limitations and edge cases

  • Generic type arguments are normally unavailable at runtime, although frameworks can preserve them using a type token or subclass metadata.
  • Static fields cannot use a class's type parameter.
  • Primitive types cannot be generic arguments; use wrappers such as Integer.
  • Heap pollution can occur through raw types, unchecked casts, arrays, or unsafe varargs.
  • Reflection can bypass normal access checks and has performance and security implications.
  • SOURCE, CLASS, and RUNTIME retention control annotation visibility.

Real-world examples

Spring's @RestController, Jackson's serialization annotations, JUnit's @Test, and Bean Validation annotations are all examples of metadata-driven behavior. Generic repositories such as Repository<Order, Long> communicate type information to the compiler and sometimes to frameworks through reflection metadata.

Follow-up questions

  • Why can you not create new T()? Erasure removes the runtime type, so the compiler cannot know which constructor to call.
  • What is a bounded type parameter? A declaration such as <T extends Number> restricts accepted types and exposes the bound's operations.
  • What is the difference between reflection and annotation processing? Reflection runs at runtime; annotation processors inspect source during compilation and can generate code.

Interview-ready answer

Generics give compile-time type safety, but Java usually implements them through type erasure and inserts casts into bytecode. Reflection inspects runtime classes and members. Annotations provide metadata, and runtime-retained annotations can be read by frameworks such as Spring. The trade-off is that generic type arguments are usually unavailable at runtime and raw or unchecked operations can create heap pollution.

Compile-time generic checking

The compiler checks that values added to a parameterized type match its type argument. When a value is read, the compiler inserts the required cast. This gives source-level safety without creating a separate runtime class for every type argument.

import java.util.*;

public class GenericSafetyDemo {
    static <T> T first(List<T> values) {
        return values.get(0);
    }

    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("Maya");
        String first = first(names);
        System.out.println(first);
    }
}

Expected output: Maya. The generic method preserves the relationship between the input and return type at compile time.

Wildcards and type variance

  • List<? extends Number> is a producer: safely read numbers, but cannot add an arbitrary Number.
  • List<? super Integer> is a consumer: safely add Integers, but reads return Object.
  • List<T> is used when a method needs to preserve or relate one exact type parameter.
static double total(List<? extends Number> values) {
    return values.stream().mapToDouble(Number::doubleValue).sum();
}

static void addDefaults(List<? super Integer> values) {
    values.add(0);
    values.add(1);
}

The mnemonic is PECS: Producer Extends, Consumer Super. It is a design rule for method APIs, not a rule that changes the runtime representation.

Type erasure limitations

  • You cannot use new T() without supplying a factory or class token.
  • You cannot create a generic array such as new T[10] safely.
  • You cannot overload methods only by generic type arguments because their erased signatures collide.
  • Use a type token such as Class<T> or a framework type reference when runtime type information is required.
static <T> T create(Class<T> type) throws ReflectiveOperationException {
    return type.getDeclaredConstructor().newInstance();
}

Reflection versus annotation processing

Reflection runs after compilation and can inspect loaded classes. Annotation processing runs during compilation and can validate source or generate code. Runtime reflection is flexible but may cost startup time and can be affected by module access, native-image restrictions, or obfuscation. Compile-time generation can improve startup and fail earlier.

Frameworks often combine both: Spring scans class metadata, builds bean definitions, and then uses reflection or generated accessors to create and wire objects. Retention policy determines whether an annotation is available to that runtime scanner.

Heap pollution and raw types

List raw = new ArrayList<String>();
raw.add(42); // unchecked operation

List<String> names = raw;
// String value = names.get(0); // ClassCastException at the inserted cast

Use compiler warnings as design feedback. If unchecked conversion is unavoidable, isolate it in a small, documented boundary and validate the data immediately.

Additional follow-up answers

  • Why are generic arrays unsafe? Arrays retain their component type at runtime, while generic arguments are erased, so the two type systems can conflict.
  • What is reification? Reification means type information is available at runtime. Java reifies raw class and array types but generally erases generic arguments.
  • What does Class<?> mean? A Class object for some unknown type; it is safer than a raw Class.
  • When use annotation processing? For compile-time validation or generated mappings, clients, configuration, and metadata when runtime reflection would be costly or fragile.
