Question: How do Spring profiles work, and what happens when application.yml and application.properties both define the same property?

Short answer

Profiles select environment-specific beans and configuration documents. Profile-specific files are applied when the profile is active. If two property files define the same key at the same precedence, the later or more specifically loaded property source wins according to Boot's documented configuration ordering; do not rely on file format alone.

Safe design

  • Use one canonical format per service when possible.
  • Keep profile files focused on environment differences.
  • Activate profiles through deployment configuration, not source-code defaults.
  • Verify the effective value with tests and a secured configuration diagnostic.

Interview follow-up

Can profiles replace secrets management? No. Profiles select configuration; secrets belong in a secret store or protected runtime injection mechanism.

I would avoid ambiguous duplicate keys and verify the final Environment rather than guessing from filenames.

Failure modes

A profile may be inactive, a profile group may activate an unexpected profile, or an environment variable may override a carefully reviewed file. Duplicate keys across YAML and properties files create maintenance risk even when Boot has a deterministic ordering. Treat one source as authoritative and test the effective configuration for each deployment profile.
