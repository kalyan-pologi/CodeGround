Question: What does spring-boot-starter-web add to an application, and how do its transitive dependencies lead to an embedded web server?

Short answer

The starter is a curated dependency bundle. It brings Spring MVC, JSON conversion, validation support, logging, and an embedded servlet container through transitive dependencies. Boot then uses classpath conditions to create the MVC infrastructure and embedded server automatically.

How to explain it

  1. A starter expresses a capability; it is not itself the web server.
  2. Spring Boot's dependency management selects compatible versions.
  3. Classpath detection sees MVC and Tomcat classes, then servlet-web auto-configuration registers the dispatcher servlet and server factory.
  4. Removing Tomcat and adding another supported container changes the runtime without changing controller code.

Common mistakes

  • Assuming a starter contains application code.
  • Ignoring dependency convergence when overriding managed versions.
  • Exposing actuator or error details just because the web starter is present.
I would describe the starter as a dependency and versioning convention. Auto-configuration observes those dependencies and creates the MVC and embedded-server beans only when their conditions match.

Internal flow

  1. The build tool resolves the starter and its managed transitive dependencies.
  2. Boot detects servlet classes, MVC classes, JSON converters, and a server implementation.
  3. Conditional configuration registers a ServletWebServerApplicationContext, MVC infrastructure, and a server factory.
  4. Context refresh starts the server and publishes the listening port.

Production example

If a deployment starts successfully but returns connection errors, check container port mapping, server.address, readiness probes, and ingress before changing controllers. If the application has an unexpected server, inspect the resolved dependency tree for multiple container implementations.

Interview-ready answer

spring-boot-starter-web supplies a compatible MVC and servlet stack. Boot sees those classes, conditionally creates the dispatcher and embedded server, and starts it during context refresh. I verify the resolved dependency tree and container port mapping when runtime behavior differs from expectations.
