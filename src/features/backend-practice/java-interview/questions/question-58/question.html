Question: Write Java Streams code to find the second-highest distinct salary in each department, group employees by department, and handle duplicate salaries.

Short answer

First group employees by department. Within each group, extract salary, remove duplicates, sort descending, skip the highest distinct value, and take the next one. Define behavior for a department with fewer than two distinct salaries: return an empty Optional or a clear “none,” not an exception. Duplicates must not count as the second-highest salary.

Runnable Java 17 program

Save as SecondSalaryByDepartment.java.

import java.util.*;
import java.util.stream.Collectors;

public class SecondSalaryByDepartment {
    record Employee(String name, String department, int salary) {}

    static Optional<Integer> secondHighest(List<Employee> employees) {
        return employees.stream()
            .map(Employee::salary)
            .distinct()
            .sorted(Comparator.reverseOrder())
            .skip(1)
            .findFirst();
    }

    public static void main(String[] args) {
        List<Employee> employees = List.of(
            new Employee("A", "Engineering", 130),
            new Employee("B", "Engineering", 130),
            new Employee("C", "Engineering", 110),
            new Employee("D", "Sales", 90),
            new Employee("E", "Sales", 80),
            new Employee("F", "Sales", 80),
            new Employee("G", "HR", 70));

        Map<String, List<Employee>> byDepartment = employees.stream()
            .collect(Collectors.groupingBy(Employee::department, TreeMap::new,
                Collectors.toList()));

        byDepartment.forEach((department, members) ->
            System.out.println(department + ": count=" + members.size()
                + ", second=" + secondHighest(members)
                    .map(String::valueOf).orElse("none")));
    }
}

Expected output:

Engineering: count=3, second=110
HR: count=1, second=none
Sales: count=3, second=80

TreeMap makes department output order deterministic; a regular HashMap would not guarantee that order.

Internal working and complexity

groupingBy makes one list per department. For each list, distinct() removes duplicate salary values, descending sort orders them, and skip(1) ignores the highest. Sorting all salaries costs roughly O(n log n) per department and stores values. For very large streams, keep only the top two distinct values in one pass or let the database calculate a rank/window function; do not load millions of employees just for a report.

Real-world edge cases and follow-ups

Specify whether salary is an exact annual amount, cents, or decimal currency; avoid double for money. Handle null department/salary according to a stated policy before grouping. A tie at the highest salary remains one distinct value. Empty departments are absent from the grouping unless seeded separately. Parallel streams rarely help for small groups and complicate ordering/performance.

  • Why distinct() before skip(1)? Two employees tied for top salary must not make that salary “second.”
  • What if all salaries are equal? There is no second distinct salary; return empty/none.
  • How do you get employees earning the second salary? Compute the value, then filter the department's employees by that salary.
  • Could SQL be better? Yes, a ranked query can avoid moving a large dataset into Java.

Interview-ready answer

I group employees by department, map each group to salaries, remove duplicates, sort descending, skip the maximum, and take the next value as an Optional. This handles tied top salaries and departments with fewer than two distinct salaries. For large datasets I would use a one-pass top-two collector or a database window function instead of sorting everything in memory.
