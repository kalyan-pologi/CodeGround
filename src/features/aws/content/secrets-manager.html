Secrets Manager

Keep database passwords and API tokens out of code, with controlled retrieval and a plan for rotation.

01 · What & Why

AWS Secrets Manager stores sensitive values as encrypted, versioned secrets and can coordinate rotation. It is useful for database passwords and third party API tokens that cannot be replaced with IAM roles. Moving a secret to a managed store reduces accidental exposure in repositories and images, but it does not make access control optional.

02 · How it works

A caller with permission requests a secret by ARN. Secrets Manager checks IAM, decrypts the current version, and returns the value over TLS. Rotation creates a new version and updates the downstream system through a configured rotation workflow. Caches reduce API calls but need an expiry policy so rotated values eventually reach the process.

03 · Reidy.AI usage

Example deployment pattern: The Appraisal Service needs an RDS password and perhaps a document generation API token. Store each as a separate secret. Give only the service that needs it GetSecretValue permission. Use an IAM role directly for S3, where a password is unnecessary.

04 · Implementation

Create a secret, choose its KMS key, and grant the ECS task role access to its ARN. For a startup fetch, the AWS SDK for Java v2 can retrieve a JSON secret. ECS can also inject a secret at task startup using the task execution role; the injected environment value stays fixed until the task restarts.

@Bean
SecretsManagerClient secretsClient(@Value("${aws.region}") String region) {
    return SecretsManagerClient.builder()
        .region(Region.of(region)).build();
}

String loadSecret(SecretsManagerClient client, String secretArn) {
    return client.getSecretValue(GetSecretValueRequest.builder()
        .secretId(secretArn).build()).secretString();
}

Do not log the returned string. Validate its expected fields before using it for spring.datasource. If you use a custom KMS key, include the required decrypt permission.

07 · Follow-up questions

  • What is rotation? Replacing a credential and updating the system that accepts it.
  • Does an ECS secret injection update live tasks? No, tasks need a restart to receive new injected values.
  • Why cache? To reduce latency and API calls, while accepting a bounded staleness window.
  • What if KMS denies decrypt? Secret retrieval can fail even with Secrets Manager permission.
  • Can IAM replace a database password? Sometimes IAM database authentication is available, but suitability depends on engine and connection pattern.

08 · Top 5 interview questions

  1. Why use Secrets Manager?

    It centralizes encrypted secrets, access control, versioning, and optional rotation.

  2. How does Spring Boot read a secret?

    Its ECS role can call GetSecretValue through the AWS SDK, or ECS can inject the value when starting the task.

  3. How do you handle rotation?

    Rotate the downstream credential, refresh or restart consumers, and watch authentication failures during the transition.

  4. How do you enforce least privilege?

    Grant a task role access only to the specific secret ARN and any required KMS action.

  5. Should a service fetch secrets on every request?

    No. Fetch at startup or cache for a bounded period to avoid extra latency and service load.

Interview answer depth

Secrets Manager: Explain encrypted, versioned values, IAM retrieval, KMS decryption, and optional rotation. Storage alone is not enough; the task role still needs narrowly scoped access.

Spring Boot: Retrieve at startup or through a bounded cache, parse the expected JSON shape, and redact values from logs and exceptions.

Rotation: Rotation must update both the secret and the downstream system. Consumers need refresh or restart behavior, and you should monitor authentication failures during the transition.

ECS injection: A task definition can inject a secret at startup, but a running task does not receive a changed environment value automatically. Restart or implement runtime refresh.

Failure handling: Check secret ARN, task role, resource policy, and customer-managed KMS key permissions before broadening access.
