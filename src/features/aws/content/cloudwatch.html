CloudWatch

Turn application logs and AWS metrics into useful dashboards, alarms, and incident evidence.

01 · What & Why

Amazon CloudWatch collects operational telemetry: metrics, logs, dashboards, and alarms. It helps answer whether the Appraisal API is healthy, how long reports take, and when failures began. An alarm is only useful when it points to an actionable condition and a response owner.

02 · How it works

AWS services publish standard metrics. ECS can route container stdout and stderr to CloudWatch Logs, where log groups and streams organize events. An application may publish custom metrics through an integration such as Micrometer. Alarms evaluate metric periods and thresholds; they can notify an SNS topic or drive supported automation.

03 · Reidy.AI usage

Example deployment pattern: Dashboard the Appraisal Service request rate, error rate, p95 latency, ECS task health, and RDS connection count. Alarm when report generation fails repeatedly or the ALB has too few healthy targets. Include a report ID and correlation ID in structured logs, but never a password or full sensitive report.

04 · Implementation

Configure the ECS task definition with the awslogs log driver, a log group, stream prefix, and region. Give the execution role log publishing permissions. In Spring Boot, use Actuator and Micrometer for application measurements and add explicit business metrics for report outcomes.

# application.yml
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus
  metrics:
    tags:
      service: appraisal-api

// Example application metric
@Service
class ReportMetrics {
    private final Counter failures;
    ReportMetrics(MeterRegistry registry) {
        failures = registry.counter("appraisal.report.failures");
    }
    void failed() { failures.increment(); }
}

Exposing a Prometheus endpoint alone does not send metrics to CloudWatch. Add a compatible collector or exporter, such as the CloudWatch agent or OpenTelemetry Collector, and verify the metric actually arrives. Set log retention and alarm notification targets.

07 · Follow-up questions

  • Metric versus log? A metric is a numeric time series; a log is an event record.
  • What is an alarm? A rule that evaluates metric data over time and changes state.
  • Why a correlation ID? To connect events from one request across services.
  • How do you monitor RDS? Use connection, CPU, storage, and latency metrics alongside application errors.
  • What does CloudTrail add? Audit records of supported AWS API activity.

08 · Top 5 interview questions

  1. What is CloudWatch?

    It is AWS operational telemetry for logs, metrics, dashboards, and alarms.

  2. What would you monitor for an API?

    Request errors and latency, healthy targets, task restarts, and database connections, plus business failures.

  3. How do ECS logs arrive?

    The task log driver sends stdout and stderr using permissions on the ECS execution role.

  4. How do you create an actionable alarm?

    Alert on sustained user impact, include a clear owner and runbook, and tune it against normal behavior.

  5. CloudWatch versus CloudTrail?

    CloudWatch is for operations; CloudTrail is for supported API activity and audit investigation.

Interview answer depth

CloudWatch: Separate logs, metrics, dashboards, and alarms. Logs explain individual events; metrics show trends; alarms turn sustained conditions into action.

Spring Boot: Emit structured JSON logs with correlation IDs, expose Actuator metrics, and publish application signals such as report failure count and latency.

ECS logs: The awslogs driver sends stdout and stderr using execution-role permissions. Check region, log group, stream prefix, and task events when logs are missing.

Alarm quality: Alert on user impact and sustained thresholds, include an owner and runbook, and avoid thresholds that page on normal short-lived variation.

CloudWatch versus CloudTrail: CloudWatch is operational telemetry; CloudTrail records supported AWS API activity. Use both when investigating an incident.
