ECS

Deploy and operate Spring Boot containers with task definitions, services, health checks, and scaling.

01 · What & Why

Amazon Elastic Container Service orchestrates containers. A task definition describes the image, CPU, memory, ports, environment, and roles. A service keeps the desired number of tasks running and manages deployments. Fargate supplies serverless container capacity; the EC2 launch type runs tasks on instances you manage.

02 · How it works

ECS schedules tasks in a cluster, pulls the image using the execution role, starts containers, and registers healthy tasks with a load balancer. A rolling deployment starts replacement tasks and removes old tasks according to deployment limits. Service Auto Scaling changes desired count using demand metrics.

Task definitionImage and settings→ECS serviceMaintains count→Fargate taskRuns container→ALBRoutes traffic

03 · Reidy.AI usage

Example deployment pattern: The Appraisal API and Report API run as separate ECS services in private subnets. Each gets its own task role and secret access. A public ALB routes HTTPS requests to the API tasks; S3 stores PDFs and RDS stores records. This is a realistic design example, not a claim about the current infrastructure.

04 · Implementation

Build the image, push it to ECR, register a task definition, then create an ECS service linked to an ALB target group. Configure the Spring Boot port and readiness endpoint consistently in the container definition and load balancer.

# application.yml
server:
  port: 8080
management:
  endpoint:
    health:
      probes:
        enabled: true

# task definition fields (illustrative)
"taskRoleArn": "arn:aws:iam::ACCOUNT:role/appraisal-task",
"executionRoleArn": "arn:aws:iam::ACCOUNT:role/ecs-execution",
"containerDefinitions": [{
  "name": "appraisal-api",
  "image": "ACCOUNT.dkr.ecr.REGION.amazonaws.com/appraisal@sha256:DIGEST",
  "portMappings": [{"containerPort": 8080}]
}]
@RestController
@RequestMapping("/api/appraisals")
class AppraisalController {
    private final ReportService reports;
    AppraisalController(ReportService reports) { this.reports = reports; }

    @GetMapping("/{id}")
    ResponseEntity<ReportStatus> status(@PathVariable UUID id) {
        return ResponseEntity.ok(reports.status(id));
    }
}

This controller delegates business state to a service. The ALB should use the separate Actuator readiness endpoint for health checks, not a business request.

The task role serves application SDK calls. The execution role serves image pulls, log delivery, and supported startup secret retrieval. Use a CloudWatch log configuration and explicit CPU and memory limits.

07 · Follow-up questions

  • Task versus service? A task is a running copy; a service maintains copies and deploys updates.
  • Task role versus execution role? Application permissions versus ECS infrastructure permissions.
  • What is Fargate? Managed compute capacity for containers without managing EC2 hosts.
  • How do tasks discover each other? Use an ALB or supported service discovery mechanisms.
  • How do you rollback? Deploy the previous task definition and image digest after diagnosing health.

08 · Top 5 interview questions

  1. What is ECS?

    It is AWS container orchestration. I define a task and use a service to keep the required number healthy.

  2. How do you deploy Spring Boot?

    Push an image to ECR, register a task definition, and update a service behind an ALB.

  3. How do you provide AWS access?

    Attach a scoped task role; keep ECR pull and log permissions on the execution role.

  4. How does ECS handle failure?

    A service starts replacement tasks, while health checks keep failing tasks out of traffic.

  5. How do you scale safely?

    Scale task count with metrics, then verify database connections, downstream limits, and load balancer health.

Interview answer depth

ECS: Distinguish cluster, task definition, task, service, target group, and capacity provider. This shows how a desired count becomes running traffic-serving containers.

Spring Boot: Describe ECR image pull, port mapping, ALB readiness, graceful shutdown, task role, execution role, and CloudWatch logs in one deployment narrative.

Failure: A service replaces stopped tasks, but a crash loop can continue. Use stop reasons, health checks, deployment events, and memory metrics to find the cause.

Scaling: Task count affects RDS connections, downstream APIs, and queue consumers. Set autoscaling limits with those dependencies in mind.

Fargate versus EC2: Fargate removes host operations; ECS on EC2 offers more capacity and host control. The application container contract remains similar.
