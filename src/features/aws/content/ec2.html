EC2

Run a Spring Boot service on an AWS virtual machine and understand the operational work that comes with host control.

01 · What & Why

Amazon Elastic Compute Cloud provides virtual machine instances. You choose an AMI, CPU and memory size, block storage, and network settings. EC2 makes sense when you need host level control or must run software that does not fit a managed runtime.

Ownership boundary

AWS runs the physical infrastructure. Your team manages the guest OS, patches, application process, and instance configuration.

02 · How it works

An instance starts from an AMI inside a VPC subnet. A security group filters traffic, an EBS volume usually holds the root filesystem, and an instance profile exposes temporary IAM role credentials. An Auto Scaling group can replace unhealthy instances and change capacity. A load balancer distributes requests to healthy targets.

03 · Reidy.AI usage

Example deployment pattern: The Appraisal API could run as a JAR on two EC2 instances in private subnets. An Application Load Balancer exposes the HTTPS API. Each instance assumes an IAM role for S3 access, while the database stays private. This is illustrative, not confirmation of the current deployment.

04 · Implementation

Build a Spring Boot JAR, create an AMI or bootstrap instances, and run the process with systemd so it restarts after failure. Configure the target group health check to a Spring Boot Actuator readiness endpoint.

# application.yml
server:
  port: 8080
management:
  endpoint:
    health:
      probes:
        enabled: true

# systemd service excerpt
[Service]
User=app
ExecStart=/usr/bin/java -jar /opt/reidy/appraisal.jar
Restart=on-failure
@SpringBootApplication
public class AppraisalApplication {
    public static void main(String[] args) {
        SpringApplication.run(AppraisalApplication.class, args);
    }
}

Package this entry point as an executable JAR. During an ALB rolling replacement, enable server.shutdown: graceful so in-flight requests can finish before the instance exits.

Attach an instance profile to the launch template. Allow port 8080 only from the load balancer security group; keep outbound access and database rules as narrow as the application permits.

06 · Edge cases

ALB reports unhealthyCheck port, health path, startup time, security groups, and process logs.
One instance disappearsAuto Scaling replaces it; keep user state and files outside the instance.
Deployment fails midwayUse rolling replacement and a health gate; retain the previous AMI for rollback.
CPU or memory pressureInspect CloudWatch, JVM heap, and request rates before changing instance size.
SSH exposurePrefer Session Manager and avoid public inbound SSH rules.

07 · Follow-up questions

  • What is an AMI? A template used to launch instances.
  • What is an instance profile? The mechanism that attaches an IAM role to EC2.
  • Security group or NACL? A security group is stateful and attached to network interfaces; a NACL is stateless and applied to subnets.
  • Where should application files live? Persistent shared files belong in S3 or another external store, not only on the instance.
  • How do you deploy without downtime? Replace instances gradually behind a health checked load balancer.

08 · Top 5 interview questions

  1. What is EC2?

    It is AWS virtual compute. I use it when I need OS and runtime control, while planning for patching, scaling, and failover myself.

  2. How do you run Spring Boot on EC2?

    Build a JAR, run it as a managed service, expose it through an ALB, and configure health checks and logging.

  3. How does an instance access S3?

    Attach an IAM role through an instance profile and let the SDK use temporary credentials.

  4. How do you make it highly available?

    Run an Auto Scaling group across multiple Availability Zones behind an ALB and keep state outside the instances.

  5. How do you investigate a 502?

    Check target health, port and security group rules, application startup, and ALB and application logs.

10 · Quick revision notes

  • AMI launches an instance.
  • EBS provides block storage.
  • Security group filters instance traffic.
  • Instance profile supplies role credentials.
  • ALB routes to healthy targets.
  • Auto Scaling replaces and scales instances.
  • Keep durable state outside the host.
  • Patch OS and AMIs regularly.

Interview answer depth

EC2: Explain the shared responsibility boundary: AWS runs physical infrastructure, while your team owns the guest OS, JVM, patches, and process supervision.

Spring Boot: Mention an executable JAR, systemd, graceful shutdown, Actuator readiness, ALB health checks, and CloudWatch logs. This turns “run a JAR” into an operable deployment answer.

IAM: Describe an instance profile and temporary role credentials instead of access keys on disk. Include how you would restrict the security group to the ALB.

Availability: Explain multiple Availability Zones, Auto Scaling replacement, and externalized state. A single large instance is not high availability.

Debugging: Walk from ALB target health to listener rules, network permissions, process startup, JVM memory, and logs. State what evidence you would collect before changing capacity.
