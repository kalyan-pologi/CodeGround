IAM

Give each person and workload only the AWS permissions it needs. Follow one report upload from an ECS task to a private S3 bucket.

01 · What & Why

Identity and Access Management (IAM) decides who can make an AWS request and which actions that identity may perform. The Appraisal Service may upload a PDF to S3; that does not mean it should be able to delete the bucket.

ConceptPurposeExample
UserLong lived identity for a person or legacy integrationDeveloper with console access
GroupCollection of IAM usersDevelopers sharing a permission set
RoleAssumable identity that supplies temporary credentialsECS task role for the Appraisal Service
PolicyJSON rules that allow or deny actions on resourcess3:PutObject for one bucket prefix
Remember

A role is an identity. A permissions policy says what it can do. A trust policy says who can assume the role.

02 · How it works

On ECS, the SDK obtains temporary credentials for the task role through the container credentials endpoint. It signs the S3 request. AWS then evaluates the applicable identity policy, bucket policy, organization controls, and explicit denies.

Spring BootCalls S3 SDK→Task roleTemporary credentials→S3Evaluates access→ResultAllow or deny

An explicit deny wins over an allow. Credentials expire, so use the SDK default provider chain to refresh them rather than caching access keys yourself.

03 · Reidy.AI usage

Example deployment pattern: The Appraisal Service generates a report PDF and uploads it under appraisals/. The Report Service downloads the PDF. Give each ECS service its own task role, scoped to the actions and object prefixes it needs. This illustrates a possible deployment, not a claim about the current project configuration.

  1. React asks the API to create an appraisal report.
  2. Spring Boot generates the PDF.
  3. The Appraisal Service uploads the object using its ECS task role.
  4. Only after S3 succeeds, the service stores the object key in RDS.

04 · Implementation

Attach this permissions policy to the Appraisal Service task role. The resource ARN targets objects, not the bucket itself.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:PutObject"],
    "Resource": "arn:aws:s3:::reidy-reports/appraisals/*"
  }]
}

Configure the ECS task definition with taskRoleArn. Keep image pulling and log publishing on the separate executionRoleArn. In Java, omit hardcoded credentials and let the SDK use its default provider chain.

@Bean
S3Client s3Client(@Value("${aws.region}") String region) {
    return S3Client.builder()
        .region(Region.of(region))
        .build();
}

@Service
class ReportStorageService {
    private final S3Client s3;
    ReportStorageService(S3Client s3) { this.s3 = s3; }

    void upload(String reportId, Path pdf) {
        s3.putObject(PutObjectRequest.builder()
                .bucket("reidy-reports")
                .key("appraisals/" + reportId + ".pdf")
                .build(), RequestBody.fromFile(pdf));
    }
}

The AWS SDK for Java v2 supplies credentials at request time. For local development, use a configured AWS profile or SSO session rather than putting keys in application.yml.

The task role authorizes application access to S3. The execution role lets ECS pull from ECR and send logs to CloudWatch. They serve different callers even though both attach to a task definition.

06 · Edge cases

SymptomCheck and recovery
AccessDenied despite an allowCheck bucket policy, explicit denies, SCPs, object ARN, and KMS permissions.
Wrong role usedInspect task definition roles and verify credentials inside the running task.
Keys leakedDisable or rotate them, review CloudTrail activity, and remove them from code and logs.
Permission is too broadReplace s3:* on * with required actions and resource ARNs.
Local code cannot authenticateUse an AWS profile or SSO; verify account and region before testing.

07 · Follow-up questions

  • Who can assume a role? Its trust policy defines permitted principals and conditions.
  • What is STS? Security Token Service issues temporary credentials when roles are assumed.
  • What if both allow and deny match? Explicit deny wins.
  • How do you audit API use? Inspect supported events in CloudTrail.
  • Does an IAM allow guarantee S3 access? No. Resource policy, organization controls, and KMS can still block it.

08 · Top 5 interview questions

  1. What is IAM?

    IAM controls AWS identities and permissions. I use roles for workloads and narrowly scoped policies for the resources they call.

  2. User versus role?

    A user is a long lived identity. A role is assumed to obtain temporary credentials, which is the usual choice for ECS and EC2 workloads.

  3. What is least privilege?

    Grant only the actions and resources a workload needs, such as s3:PutObject for one reports prefix.

  4. How does Spring Boot get AWS credentials on ECS?

    The default credentials provider chain discovers temporary task role credentials, so the application does not need embedded access keys.

  5. Task role versus execution role?

    The task role is for application code. The execution role is for ECS infrastructure actions such as pulling from ECR and publishing logs.

Interview answer depth

IAM: Explain the policy evaluation model: identity policy, resource policy, permissions boundary, SCP, and explicit deny. Then connect it to the design: an ECS task role receives only the S3 prefix permissions required by the service.

Roles: Contrast temporary role credentials with long-lived user keys, and mention trust policies and STS. This demonstrates that you understand both authentication and authorization.

Least privilege: Give a concrete ARN and action rather than saying “limited access.” Explain how you would review CloudTrail and remove unused actions after observing the service.

Spring Boot: Describe the AWS SDK default provider chain and why credentials stay out of application.yml. Mention local profiles or SSO for development and task roles in ECS.

Operations: Separate task and execution roles, then explain how you would investigate AccessDenied without broadening permissions as a first response.
