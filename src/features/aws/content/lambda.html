Lambda

Run bounded, event driven Java work without operating a continuously running server.

01 · What & Why

AWS Lambda invokes your function when an event arrives and scales concurrent invocations within configured limits. It is useful for short background processing, scheduled jobs, and event handlers. A full Spring Boot API can run in Lambda with adapters, but startup cost and runtime model need careful evaluation.

02 · How it works

An event source invokes a function version or alias. Lambda creates or reuses an execution environment, passes the event to a handler, and records the result. Each invocation has a timeout, memory allocation, and execution role. Asynchronous sources can retry; duplicate delivery is possible, so handlers should be idempotent.

03 · Reidy.AI usage

Example deployment pattern: After the Appraisal Service writes a PDF to S3, an S3 notification invokes a Java Lambda function to create a preview image. The function writes the preview under a separate prefix. This isolates optional postprocessing from the request path and lets it retry independently.

04 · Implementation

Create the function with a supported Java 17 runtime, a handler class, an execution role, memory and timeout limits, and an S3 event notification. Add the AWS Lambda Java runtime interface dependency through Maven. Avoid configuring the destination prefix to trigger the same function unless you explicitly filter events, or it may loop.

public class ReportPreviewHandler
        implements RequestHandler<S3Event, String> {
    private final S3Client s3 = S3Client.create();

    @Override
    public String handleRequest(S3Event event, Context context) {
        var record = event.getRecords().get(0);
        String key = record.getS3().getObject().getUrlDecodedKey();
        // Skip keys already processed; create preview with a stable output key.
        return key;
    }
}

The example illustrates the S3 event shape and SDK setup; the preview conversion is application specific. Derive an idempotency key from bucket, object key, and version or ETag, then persist a processed record before applying a credit or notification side effect. Grant only source read and destination write permissions. Use a function alias for releases and a failure destination or dead letter path appropriate to the invocation type.

06 · Edge cases

RiskMitigation
Duplicate eventUse stable output keys or an idempotency record; do not assume exactly once delivery.
Recursive S3 triggerFilter source prefix or suffix and write results elsewhere.
Cold start delayKeep dependencies lean and measure Java startup; use provisioned concurrency only if justified.
Timeout or partial failureSet a realistic timeout and retry path; make side effects safe to repeat.
High concurrency exhausts RDSLimit concurrency or use a proxy and connection reuse.

07 · Follow-up questions

  • What is a cold start? The latency to initialize a new execution environment.
  • Can local state persist? It may persist on a reused environment, but cannot be relied on.
  • What is reserved concurrency? A cap and reservation of concurrent executions for a function.
  • How are async errors handled? Through retries and configured failure destinations or dead letter options.
  • Can a handler be retried? Yes; duplicate safe behavior is essential.

08 · Top 5 interview questions

  1. What is Lambda?

    It runs event triggered code without a server process I keep alive, within time and resource limits.

  2. When would you use it here?

    For bounded PDF postprocessing or notifications after an S3 event, not automatically for the main API.

  3. How do you avoid duplicate work?

    Use an idempotency key based on event or object identity and make writes repeatable.

  4. How does it access S3?

    An execution role grants narrow S3 actions; the Java SDK obtains temporary credentials.

  5. How do you debug failures?

    Inspect CloudWatch logs, error and duration metrics, source retry behavior, and failure destination records.

Production practice

If the same S3 event arrives twice, do not deduct credits or send two notifications. Store a unique processing record keyed by the object version or appraisal ID, check it before side effects, and make the handler safe to retry. Configure retries and a failure destination for events that still fail.

Interview answer depth

Lambda: Explain invocation type, execution environment, timeout, memory, concurrency, and execution role. It is a bounded function model, not merely “a serverless server.”

Java: Keep dependencies and initialization lean, reuse clients across warm invocations, and measure cold starts before choosing provisioned concurrency.

Idempotency: S3 and asynchronous sources can deliver duplicate events. Use an object-derived idempotency key and stable output path before writing side effects.

Retries: Configure retry and failure destination behavior for the event source. Make downstream calls safe to retry and avoid infinite trigger loops.

Database access: Concurrent invocations can exhaust RDS connections. Limit concurrency, reuse connections correctly, or use RDS Proxy when the workload justifies it.
