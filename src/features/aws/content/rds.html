RDS

Use a managed relational database for transactional records while planning connections, failover, backups, and migrations.

01 · What & Why

Amazon Relational Database Service provisions and operates supported relational engines such as PostgreSQL and MySQL. It automates parts of maintenance, backup, and recovery. Your team still owns schemas, indexes, query behavior, migration safety, and connection management.

02 · How it works

An RDS instance has a database endpoint inside a VPC. The Spring Boot connection pool opens database sessions through that endpoint. In a Multi AZ deployment, RDS can fail over to a standby; existing connections break and the application must reconnect. Read replicas are separate asynchronous copies for read traffic, not a substitute for failover.

03 · Reidy.AI usage

Example deployment pattern: Store appraisal records, report state, and S3 object keys in a private RDS PostgreSQL database. The Appraisal and Report services use separate database users or schemas when practical. The object bytes remain in S3.

04 · Implementation

Create a private DB subnet group, permit inbound database traffic only from ECS task security groups, and store credentials in Secrets Manager. Run Flyway migrations during a controlled deployment step. Size HikariCP across all service replicas.

# application.yml
spring:
  datasource:
    url: ${DB_JDBC_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
    hikari:
      maximum-pool-size: 8
  flyway:
    enabled: true

@Entity
class AppraisalReport {
    @Id UUID id;
    String s3ObjectKey;
    String status;
}

The runtime can receive database credentials through an approved Secrets Manager integration or ECS secret injection. Keep the values out of source files and logs.

06 · Edge cases

RiskAction
Connection exhaustionMultiply pool size by task count; cap it below database limits or consider RDS Proxy.
Failover interrupts transactionsRetry safe operations and make writes idempotent where possible.
Slow queriesInspect plans and indexes; do not use a larger instance as the first fix.
Schema driftUse versioned migrations and test them against a fresh and existing database.
Accidental deletionEnable backups and test point in time restore, including recovery objectives.

07 · Follow-up questions

  • Does Multi AZ increase reads? Standard standby capacity serves failover, not ordinary read scaling.
  • What is a read replica? An asynchronously replicated copy for read workloads.
  • What is RDS Proxy? A managed proxy that pools and shares database connections.
  • What happens during failover? Connections can drop; clients reconnect to the endpoint.
  • What does RDS not manage? Your data model, queries, app transactions, and migrations.

08 · Top 5 interview questions

  1. Why use RDS?

    It gives the service a managed relational database while preserving SQL transactions and familiar JDBC tooling.

  2. How do you connect Spring Boot securely?

    Use a private endpoint, restricted security groups, and credentials delivered from Secrets Manager.

  3. How do you handle failover?

    Use Multi AZ, configure connection timeouts, and retry only operations that are safe to repeat.

  4. How do you scale reads?

    First optimize queries and indexes; add read replicas if the read workload justifies them.

  5. How do you manage schema changes?

    Use versioned migrations, test rollback or forward recovery, and coordinate changes with application releases.

10 · Quick revision notes

  • RDS manages database infrastructure.
  • Private subnet and security group protect access.
  • Multi AZ supports failover.
  • Read replicas scale reads.
  • Pool size × task count matters.
  • Backups must be restore tested.
  • Flyway keeps schema versioned.
  • Store file keys, not file bytes.

Interview answer depth

RDS: Explain what AWS manages and what the application still owns: schema, indexes, SQL, migrations, connection pools, and transactions.

Availability: Multi-AZ is for failover; a read replica is for read scaling. Existing connections can break during failover, so the pool needs timeouts and reconnect behavior.

Spring Boot: Use HikariCP, externalized credentials, Flyway migrations, and a private endpoint. Calculate pool capacity across all ECS tasks, not one task.

Recovery: Discuss automated backups, point-in-time restore, RPO/RTO, and a tested restore procedure rather than only saying “backups are enabled.”

Performance: Check query plans, indexes, lock waits, and connection counts before increasing instance size. RDS Proxy can help with connection storms but does not fix bad SQL.
