ECR

Store versioned container images and connect a repeatable build pipeline to ECS deployments.

01 · What & Why

Amazon Elastic Container Registry is a managed registry for OCI container images. It stores the packaged Spring Boot runtime, dependencies, and application artifact that ECS will run. ECR is a distribution point for images; it does not execute them.

02 · How it works

A CI pipeline builds image layers, authenticates to ECR, and pushes a tag and immutable digest. ECS uses the image reference in a task definition. During deployment, the ECS task execution role obtains permission to pull the layers from ECR. A digest identifies exact bytes; a mutable tag can point to different bytes later.

CI buildCreates image→ECRStores layers→ECSPulls image→TaskRuns API

03 · Reidy.AI usage

Example deployment pattern: Give Appraisal and Report services separate ECR repositories. The CI pipeline pushes a unique image for each commit. A release records the image digest in the ECS task definition so a rollback restores the exact earlier build.

04 · Implementation

Create an ECR repository, enable scan on push where appropriate, and configure a lifecycle policy. Build a small multi-stage Java image; do not include credentials in build arguments or image layers. Authenticate the CI role with least privilege.

# Example build and push sequence
docker build -t appraisal-service:2026-11-19 .
aws ecr get-login-password --region us-east-1 |
  docker login --username AWS --password-stdin ACCOUNT.dkr.ecr.us-east-1.amazonaws.com
docker tag appraisal-service:2026-11-19 \
  ACCOUNT.dkr.ecr.us-east-1.amazonaws.com/appraisal-service:2026-11-19
docker push ACCOUNT.dkr.ecr.us-east-1.amazonaws.com/appraisal-service:2026-11-19
# Runtime image for a Spring Boot executable JAR
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY target/appraisal-service.jar app.jar
USER 10001
ENTRYPOINT ["java", "-jar", "/app/app.jar"]

Build the JAR with the Spring Boot Maven plugin before the image build. Match the JRE version to the project target and run as a non-root user.

Point containerDefinitions[].image in the ECS task definition to the pushed image. Grant the task execution role the ECR pull actions; application code normally does not need ECR access.

06 · Edge cases

ProblemResponse
ECS cannot pull imageCheck repository URI, tag or digest, execution role policy, and network path to ECR.
latest points to a new buildUse unique tags or digests for reproducible deployments and rollbacks.
Image includes a passwordRemove the secret, rotate it, and rebuild; deleted tags do not erase already copied layers.
Vulnerability scan flags packagesUpdate base image and dependencies, rebuild, and verify the finding is resolved.
Registry grows indefinitelyApply lifecycle rules without deleting images still needed for rollback.

07 · Follow-up questions

  • Tag versus digest? A tag is a name; a digest identifies specific image content.
  • Who pulls the image in ECS? ECS uses the task execution role.
  • Can ECR run containers? No, ECS or another runtime executes them.
  • How do you roll back? Deploy a previous task definition with its recorded image digest.
  • Does scanning replace patching? No, findings need dependency or base image remediation.

08 · Top 5 interview questions

  1. What is ECR?

    It is AWS managed container image storage that my pipeline pushes to and ECS pulls from.

  2. How do you deploy a new version?

    Build and test an image, push it, register a task definition referencing its digest, then update the ECS service.

  3. Why avoid latest?

    It is mutable, so the same reference can run different code and make rollback ambiguous.

  4. How do you secure image access?

    Use separate IAM roles for CI push and ECS pull, scoped to the required repository.

  5. What belongs in an image?

    Runtime binaries and application code, not passwords or environment specific secrets.

10 · Quick revision notes

  • ECR stores images.
  • ECS runs images.
  • Tags can move.
  • Digests identify exact bytes.
  • Execution role pulls for ECS.
  • CI role pushes images.
  • Scan and patch images.
  • Use lifecycle rules carefully.

Interview answer depth

ECR: Explain that ECR stores OCI layers while ECS executes containers. The registry is part of delivery, not the runtime.

Release safety: Build, test, scan, push, and register a task definition with an immutable digest. Record the digest so rollback is deterministic.

IAM: Separate CI push permissions from the ECS execution role's pull permissions. Application code normally should not need ECR access.

Image hygiene: Use a small JRE runtime, run as non-root, keep secrets out of layers, and rebuild when the base image has security fixes.

Operations: Use lifecycle rules to control registry growth, but retain the image digests needed for supported rollback windows.
