Stream Interview Questions — Additional Examples

These examples complete the interview checklist alongside the original snippets above. They use the existing Employee model and imports. Collections and their elements are non-null. Salary rankings count distinct salary values, not employees.

Count word frequency in a sentence

Normalize case and split on punctuation and whitespace. Apostrophes also split words here.

String sentence = "Java is fun. Java is useful!";
Map<String, Long> wordFrequency = Arrays.stream(
        sentence.toLowerCase(Locale.ROOT).split("[^\\p{L}\\p{N}]+"))
    .filter(word -> !word.isEmpty())
    .collect(Collectors.groupingBy(
        Function.identity(), TreeMap::new, Collectors.counting()));
// {fun=1, is=2, java=2, useful=1}

Find the first repeated character

“First repeated” means the character whose second occurrence appears earliest: "abccba" returns "c". This UTF-16 character example scans prefixes and can take O(n²) time.

String text = "abccba";
Optional<Character> firstRepeated = java.util.stream.IntStream
    .range(0, text.length())
    .filter(i -> text.indexOf(text.charAt(i)) < i)
    .mapToObj(text::charAt)
    .findFirst();
// Optional[c]; Optional.empty() if no character repeats

Find maximum and minimum elements

List<Integer> numbers = List.of(8, 2, 15, -3);
Optional<Integer> minimum = numbers.stream().min(Integer::compareTo);
Optional<Integer> maximum = numbers.stream().max(Integer::compareTo);
// Optional[-3], Optional[15]; both empty for an empty list

Find the top 3 highest salaries

List<Double> top3Salaries = employees.stream()
    .map(Employee::getSalary)
    .distinct()
    .sorted(Comparator.reverseOrder())
    .limit(3)
    .toList();
// Returns up to three distinct values, depending on availability.

Find the Nth highest salary

int n = 3;
if (n < 1) throw new IllegalArgumentException("n must be positive");
Optional<Double> nthHighestSalary = employees.stream()
    .map(Employee::getSalary)
    .distinct()
    .sorted(Comparator.reverseOrder())
    .skip(n - 1L)
    .findFirst();
// n = 2 gives the second-highest distinct salary.
// Empty if there are fewer than n distinct salaries.

Convert List<Employee> into Map<Id, Employee>

Map<Integer, Employee> employeesById = employees.stream()
    .collect(Collectors.toMap(Employee::getId, Function.identity()));
// Duplicate IDs throw IllegalStateException.

Find all employees whose names start with a given character

Match first names case-insensitively.

char initial = 'a';
String prefix = String.valueOf(initial).toLowerCase(Locale.ROOT);
List<Employee> matchingEmployees = employees.stream()
    .filter(e -> e.getFirstName().toLowerCase(Locale.ROOT).startsWith(prefix))
    .toList();
// Every matching employee, or an empty list when none match

Find the longest string in a list

List<String> words = List.of("Java", "Spring", "microservices");
Optional<String> longest = words.stream()
    .max(Comparator.comparingInt(String::length));
// Optional[microservices]; empty for an empty list
// Length counts UTF-16 code units. Define a tie policy if required.

Find common elements between two lists

List<Integer> first = List.of(1, 2, 2, 3, 4);
List<Integer> second = List.of(2, 4, 6);
Set<Integer> secondSet = new HashSet<>(second);
List<Integer> common = first.stream()
    .filter(secondSet::contains)
    .distinct()
    .toList();
// [2, 4]: unique intersection in the first list's encounter order

Calculate salary sum and average together

DoubleSummaryStatistics salaryStats = employees.stream()
    .mapToDouble(Employee::getSalary)
    .summaryStatistics();
double salarySum = salaryStats.getSum();
OptionalDouble salaryAverage = salaryStats.getCount() == 0
    ? OptionalDouble.empty()
    : OptionalDouble.of(salaryStats.getAverage());
// Empty input: sum 0 and no average.
// For exact money arithmetic, use BigDecimal and a rounding policy.

Remove duplicate elements using Streams

List<Integer> unique = List.of(3, 1, 3, 2, 1).stream()
    .distinct()
    .toList();
// [3, 1, 2]; object equality uses equals/hashCode

Count character frequency in a string

Code points handle supplementary Unicode characters. Counts are case-sensitive and include spaces.

String text = "banana";
Map<String, Long> characterFrequency = text.codePoints()
    .mapToObj(cp -> new String(Character.toChars(cp)))
    .collect(Collectors.groupingBy(
        Function.identity(), LinkedHashMap::new, Collectors.counting()));
// {b=1, a=3, n=2}

Important Alternative Stream Implementations

Compare these approaches by the result you need. Examples use Java 17 and the same non-null Employee model. Each pair highlights a meaningful difference rather than a different spelling of the same pipeline.

1. Frequency counting: groupingBy vs toMap

Approach A — group items and count each group. This reads directly as “group identical values, then count.”

List<String> words = List.of("java", "spring", "java");
Map<String, Long> counts = words.stream()
    .collect(Collectors.groupingBy(
        Function.identity(), Collectors.counting()));

Approach B — map each item to 1 and merge duplicate keys. Useful for understanding merge functions and adapting the calculation to weighted totals.

Map<String, Long> counts = words.stream()
    .collect(Collectors.toMap(
        Function.identity(), word -> 1L, Long::sum));
// Both: {java=2, spring=1}, with unspecified map iteration order

Choose: groupingBy for grouping with downstream collectors; toMap when you naturally have a key, a value, and a merge rule. Neither needs to store lists just to count occurrences.

2. Highest salary per department: groupingBy + maxBy vs toMap + merge

Approach A — downstream maximum. Values are Optional<Employee> because maxBy also supports empty input.

Comparator<Employee> bySalary = Comparator
    .comparingDouble(Employee::getSalary)
    .thenComparingInt(Employee::getId);
Map<String, Optional<Employee>> highest = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment, Collectors.maxBy(bySalary)));

Approach B — retain the maximum when department keys collide. Values are Employee objects directly.

Map<String, Employee> highest = employees.stream()
    .collect(Collectors.toMap(
        Employee::getDepartment,
        Function.identity(),
        java.util.function.BinaryOperator.maxBy(bySalary)));

Choose: groupingBy when combining grouping with other downstream operations; toMap for a direct winner-per-key map. Both return an empty map for empty input. This comparator resolves equal salaries by choosing the higher employee ID; change that policy if needed.

3. Find one maximum: sorted + findFirst vs max

Approach A — sort all employees. Useful when you also need a ranked list or the top N.

Optional<Employee> highest = employees.stream()
    .sorted(bySalary.reversed())
    .findFirst();

Approach B — find only the maximum. Reuse the salary comparator from the previous example.

Optional<Employee> highest = employees.stream().max(bySalary);

Choose: max for a single winner: O(n) time rather than sorting in O(n log n). Use sorting with limit for multiple ranked results. Both return an empty Optional for empty input.

4. Minimum and maximum: separate terminal operations vs summaryStatistics

Approach A — two streams. Clear when you need only one of the values, or need to return the original objects using a comparator.

List<Integer> numbers = List.of(8, 2, 15, -3);
Optional<Integer> minimum = numbers.stream().min(Integer::compareTo);
Optional<Integer> maximum = numbers.stream().max(Integer::compareTo);

Approach B — collect numeric statistics in one traversal.

IntSummaryStatistics stats = numbers.stream()
    .mapToInt(Integer::intValue)
    .summaryStatistics();
if (stats.getCount() > 0) {
    System.out.println(stats.getMin()); // -3
    System.out.println(stats.getMax()); // 15
    System.out.println(stats.getAverage());
}
// Empty statistics use sentinel min/max values: check count first.

Choose: summaryStatistics when you need several numeric aggregates together. A Stream is consumed after a terminal operation, so the first approach must create two streams.

5. First repeated character: prefix search vs grouping occurrence positions

Approach A — prefix search. The earlier first-repeated-character snippet finds the earliest second occurrence using indexOf. It is simple but can take O(n²) time.

Approach B — group character positions, then find the earliest second position. This avoids repeated prefix scanning. Both examples treat characters as UTF-16 code units.

String text = "abccba";
Map<Character, List<Integer>> positions = java.util.stream.IntStream
    .range(0, text.length()).boxed()
    .collect(Collectors.groupingBy(text::charAt));
OptionalInt secondPosition = positions.values().stream()
    .filter(indices -> indices.size() > 1)
    .mapToInt(indices -> indices.get(1))
    .min();
Optional<Character> firstRepeated = secondPosition.isPresent()
    ? Optional.of(text.charAt(secondPosition.getAsInt()))
    : Optional.empty();
// Optional[c]; no repeated character produces Optional.empty()

Choose: the simple prefix version for a short example; grouping positions for expected O(n) time with O(n) extra storage. A plain loop with a HashSet is usually simpler for this specific task; forcing everything into a Stream is not always clearer.

6. Collect a list: toList vs toCollection

Approach A — unmodifiable result.

List<Integer> unique = numbers.stream().distinct().toList();
// unique.add(99) throws UnsupportedOperationException.

Approach B — explicitly mutable ArrayList.

List<Integer> unique = numbers.stream().distinct()
    .collect(Collectors.toCollection(ArrayList::new));
unique.add(99); // allowed

Choose: toList when the result should not be structurally modified; toCollection when later modifications are required. Collectors.toList() does not guarantee a particular implementation or mutability. An unmodifiable list does not make mutable Employee objects inside it immutable.

7. Filter before grouping vs filtering inside the collector

Approach A — remove employees before grouping. Departments without a matching employee disappear.

Map<String, List<Employee>> aboveThreshold = employees.stream()
    .filter(e -> e.getSalary() > 7500)
    .collect(Collectors.groupingBy(Employee::getDepartment));

Approach B — retain observed department groups, then filter their contents.

Map<String, List<Employee>> aboveThreshold = employees.stream()
    .collect(Collectors.groupingBy(Employee::getDepartment,
        Collectors.filtering(e -> e.getSalary() > 7500,
            Collectors.toList())));

Choose: filter first when only matching departments matter; downstream filtering when a department present in the input should remain with an empty list even if no employee qualifies. This does not create departments absent from the input.

8. Split even and odd: partitioningBy vs groupingBy

Approach A — a guaranteed two-way partition.

Map<Boolean, List<Integer>> byParity = numbers.stream()
    .collect(Collectors.partitioningBy(n -> n % 2 == 0));

Approach B — group by a Boolean key.

Map<Boolean, List<Integer>> byParity = numbers.stream()
    .collect(Collectors.groupingBy(n -> n % 2 == 0));

Choose: partitioningBy for a predicate: both true and false keys exist, even if a partition is empty. groupingBy contains only keys observed in the input and generalizes to more than two categories.
