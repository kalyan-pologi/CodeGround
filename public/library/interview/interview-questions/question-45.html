Question: How would you implement authentication and authorization in Spring Boot microservices using Spring Security, OAuth2, JWT, RBAC, refresh tokens, and service-to-service authentication?

Short answer

Authentication establishes who is calling; authorization decides whether that identity may perform a specific action on a specific resource. Use an OAuth2/OIDC identity provider to issue short-lived access tokens, configure each Spring Boot API as a resource server to validate JWT signature, issuer, expiry, and audience, then apply role/scope checks plus object-level ownership checks. Refresh tokens belong at the client/authorization-server boundary, not in every resource service. Service-to-service calls use workload identity or client credentials with least privilege.

Internal flow, step by step

  1. The client authenticates with the identity provider and obtains an access token for the API's audience. A refresh token, if used, is stored securely and rotated according to provider policy.
  2. The gateway may validate a token, but every service still validates the token it trusts and authorizes the requested resource.
  3. Spring Security's filter chain extracts the bearer token, verifies its signature using trusted keys, checks claims such as iss, exp, nbf, and aud, and builds an Authentication.
  4. RBAC/scope rules guard endpoints or methods; the service also checks tenant and object ownership to prevent BOLA/IDOR.
  5. For machine-to-machine calls, use client credentials or platform workload identity with separate scopes. Never forward a user's powerful token indiscriminately.

Project-ready Spring Security example

In a Spring Boot project with web, security, OAuth2 resource-server, and JOSE dependencies, configure a real issuer and audience. This filter chain requires the orders.read scope for read requests:

package demo;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
class ApiSecurity {
    @Bean
    SecurityFilterChain security(HttpSecurity http) throws Exception {
        return http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/api/orders/**").hasAuthority("SCOPE_orders.read")
                .anyRequest().authenticated())
            .oauth2ResourceServer(oauth -> oauth.jwt(Customizer.withDefaults()))
            .build();
    }
}

Expected HTTP behavior: no token → 401; valid token missing orders.read → 403; valid token with scope → endpoint handler runs. The handler must still verify that the caller owns the requested order. Configure spring.security.oauth2.resourceserver.jwt.issuer-uri and audience validation for your provider; exact properties depend on Spring Boot version.

Real-world edge cases

JWTs are signed, not automatically encrypted; do not place secrets in claims. Short expirations limit damage but make revocation non-instant unless using introspection or additional controls. Validate algorithms and key rotation through trusted provider metadata. Cookies and bearer headers have different CSRF considerations. Use HTTPS everywhere, redact tokens from logs, and test tenant boundaries. A role such as ADMIN does not automatically authorize access to every tenant.

Common follow-up interview questions and answers

  • 401 versus 403? 401 means authentication is absent/invalid; 403 means authenticated but not authorized.
  • Is a JWT enough for object authorization? No. The service must check ownership/tenant on each object.
  • Where should refresh tokens go? To the trusted client and authorization server, not routine resource-service requests.
  • How does a service call another service? Use client credentials or workload identity with narrowly scoped permissions and an appropriate delegation model.

Interview-ready answer

I use OAuth2/OIDC for identity, validate access tokens in each Spring resource server, and require issuer, signature, expiry, and audience checks. Endpoint scopes/roles are only the first authorization layer; services enforce tenant and object ownership. Refresh tokens stay with the client/identity provider, while service-to-service calls use least-privilege machine identity. I protect tokens, rotate keys, and test 401, 403, and cross-tenant access.
