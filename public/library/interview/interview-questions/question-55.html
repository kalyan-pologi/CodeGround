Question: Implement a producer-consumer system using BlockingQueue with multiple producers and consumers.

Short answer

Use a bounded BlockingQueue to hand off items safely. Producers block on put() when the queue is full, giving backpressure; consumers block on take() when empty. After all producers finish, enqueue one poison pill for each consumer, or use another explicit shutdown protocol. The queue handles synchronization and visibility, but not durability across process crashes.

import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class MultiProducerConsumer {
    private static final int STOP = -1;

    public static void main(String[] args) throws InterruptedException {
        BlockingQueue<Integer> work = new ArrayBlockingQueue<>(4);
        AtomicInteger processed = new AtomicInteger();
        AtomicInteger total = new AtomicInteger();
        Thread[] producers = new Thread[2];
        Thread[] consumers = new Thread[2];

        for (int p = 0; p < producers.length; p++) {
            final int start = p * 5 + 1;
            producers[p] = new Thread(() -> {
                try {
                    for (int n = start; n < start + 5; n++) work.put(n);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            });
        }
        for (int c = 0; c < consumers.length; c++) {
            consumers[c] = new Thread(() -> {
                try {
                    while (true) {
                        int item = work.take();
                        if (item == STOP) return;
                        processed.incrementAndGet();
                        total.addAndGet(item);
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            });
        }
        for (Thread consumer : consumers) consumer.start();
        for (Thread producer : producers) producer.start();
        for (Thread producer : producers) producer.join();
        for (int i = 0; i < consumers.length; i++) work.put(STOP);
        for (Thread consumer : consumers) consumer.join();
        System.out.println("processed=" + processed.get());
        System.out.println("sum=" + total.get());
    }
}

Expected output:

processed=10
sum=55

The order in which workers process individual items is nondeterministic; the final count and sum are deterministic.

Internal working and real-world edge cases

ArrayBlockingQueue has a fixed capacity and coordinates producers and consumers internally. put/take establish the handoff; no extra lock is needed around the queue. Poison pills are inserted only after every producer joins, so a consumer cannot stop before all real work is published. There is one pill per consumer. In production, choose a sentinel that cannot be valid data, propagate worker failures to a supervisor, enforce shutdown timeouts, and use a durable broker if items must survive a crash. Monitor queue depth and processing lag.

Common follow-up interview questions and answers

  • Why bounded queue? It bounds memory and forces producers to slow down when consumers cannot keep up.
  • What does offer() change? It can return false or time out instead of blocking indefinitely.
  • Why one poison pill per consumer? Each consumer removes only one; all consumers need their own stop signal.
  • Does BlockingQueue guarantee processing exactly once? It coordinates one in-process handoff, not durable recovery after crashes.

Interview-ready answer

I use a bounded BlockingQueue with multiple producers calling put and consumers calling take. The queue supplies thread-safe handoff and backpressure. Once producers finish, I send one stop marker per consumer, wait for them to join, and verify processed counts. For durable or cross-instance work I use a broker and idempotent consumers instead of an in-memory queue.
