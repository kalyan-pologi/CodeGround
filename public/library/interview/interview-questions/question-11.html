Question: What are the important Java 17 and Java 21 features, including records, sealed classes, pattern matching, switch expressions, and virtual threads?

Short answer

Java 17 is an LTS release with records, sealed classes, pattern matching for instanceof, text blocks, and modernized APIs. Java 21 is an LTS release that finalizes pattern matching for switch, record patterns, sequenced collections, and virtual threads. These features reduce boilerplate and improve concurrency, but they do not remove the need to manage blocking calls, memory, and service limits.

public class ModernJavaDemo {
    record User(String name, int age) {}

    sealed interface Result permits Success, Failure {}
    record Success(String value) implements Result {}
    record Failure(String message) implements Result {}

    static String describe(Result result) {
        return switch (result) {
            case Success success -> "value=" + success.value();
            case Failure failure -> "error=" + failure.message();
        };
    }

    public static void main(String[] args) throws Exception {
        User user = new User("Maya", 30);
        if (user instanceof User(String name, int age) && age >= 18) {
            System.out.println(name + " is an adult");
        }
        System.out.println(describe(new Success("ok")));
        try (var executor = java.util.concurrent.Executors.newVirtualThreadPerTaskExecutor()) {
            executor.submit(() -> System.out.println("virtual thread" )).get();
        }
    }
}

Expected output: Maya is an adult, value=ok, and virtual thread (the last line may appear in a different scheduling context).

Feature details and limitations

  • Records: concise immutable data carriers with generated accessors, constructor, equals, hashCode, and toString. A record is shallowly immutable; mutable fields still need defensive copies.
  • Sealed classes: restrict permitted subtypes and let the compiler reason about an exhaustive hierarchy.
  • Pattern matching: combines type checks, casts, record destructuring, and switch expressions in a safer form.
  • Virtual threads: are lightweight threads suited to large numbers of mostly blocking tasks. They improve concurrency, not CPU capacity, and should not be used to hide unbounded downstream calls.
  • Migration: verify library compatibility, compiler release settings, reflection behavior, container images, monitoring, and framework support before changing the runtime.

Follow-up questions

  • Are virtual threads faster than platform threads for CPU work? No. They mainly reduce the cost of waiting and allow many concurrent blocking tasks.
  • Can a record extend a class? No, records implicitly extend java.lang.Record, but they can implement interfaces.
  • Why use a sealed hierarchy? It makes domain states explicit and allows exhaustive pattern matching, which helps catch missing cases at compile time.

Interview-ready answer

Java 17 and 21 add concise data modeling and safer control flow through records, sealed classes, pattern matching, and switch expressions. Java 21 virtual threads make high-concurrency blocking workloads cheaper, but they do not make CPU work faster or remove database and downstream limits. I evaluate runtime, libraries, observability, and workload characteristics when adopting them.

Java 17 feature details

  • Records: concise nominal data carriers with final components, generated accessors, equality, hash code, and a canonical constructor.
  • Sealed classes: explicitly define permitted subclasses and make domain state transitions easier to review.
  • Pattern matching for instanceof: combines the type test and cast, reducing repeated boilerplate.
  • Text blocks: make multiline JSON, SQL, and templates easier to read.
  • Helpful NullPointerException messages: improve diagnosis by identifying the null expression in many cases.

A record is not deeply immutable. A record component such as List<String> still needs List.copyOf if callers must not mutate it. A compact constructor is useful for validation and normalization.

record Money(String currency, long cents) {
    Money {
        if (cents < 0) throw new IllegalArgumentException("negative amount");
        currency = currency.toUpperCase();
    }
}

Java 21 feature details

  • Pattern matching for switch: switch over types and values with compiler-checked exhaustiveness.
  • Record patterns: destructure record components in conditions and switch cases.
  • Sequenced collections: common first, last, and reversed operations across ordered collections.
  • Virtual threads: lightweight threads scheduled by the JVM and designed for very high numbers of mostly waiting tasks.
  • Scoped values and structured concurrency: important modern concurrency ideas; check the exact JDK release and preview status before production adoption.

Virtual threads are cheap to create, but a request that waits on a database still consumes a database connection. They improve thread scalability around blocking waits; they do not increase CPU cores, database capacity, or external API limits. Avoid pinning virtual threads with long synchronized or native sections, and measure with production-like load.

Virtual-thread example

import java.util.concurrent.Executors;

public class VirtualThreadDemo {
    public static void main(String[] args) throws Exception {
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            var first = executor.submit(() -> "order-1");
            var second = executor.submit(() -> "order-2");
            System.out.println(first.get() + "," + second.get());
        }
    }
}

Expected output: order-1,order-2. The executor creates a virtual thread per submitted task and closes after all tasks finish. It is still important to bound calls to scarce resources with connection pools, semaphores, or rate limiters.

Migration and compatibility checklist

  1. Compile with the intended --release and run the same major JDK in local, CI, and production environments.
  2. Check Spring Boot, JDBC drivers, agents, serializers, bytecode tools, and monitoring libraries for supported JDK versions.
  3. Test reflection, serialization, native libraries, and module access; newer JDKs may expose illegal assumptions.
  4. Load-test virtual threads with real downstream limits and inspect thread dumps, blocked tasks, heap, and connection pools.
  5. Use preview features only with an explicit rollout decision because syntax or behavior can change before finalization.

Additional follow-up answers

  • Are records immutable? Their components are final, but referenced mutable objects are not automatically copied.
  • Can a record extend another class? No. It implicitly extends Record, but it can implement interfaces.
  • When should virtual threads be avoided? For CPU-bound work where a bounded platform-thread pool is clearer, or when downstream systems cannot handle more concurrent requests.
  • What does exhaustive switch checking provide? The compiler can identify a missing permitted subtype or enum case, reducing runtime default-case surprises.
  • Do newer Java features change garbage collection? They change language and concurrency capabilities; GC selection and tuning remain workload and runtime concerns.
